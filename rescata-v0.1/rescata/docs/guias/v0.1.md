# Guía de la versión 0.1 · Base y diseño

**La sube:** Integrante 1 (quien crea el repositorio).
**Léela antes de subir.** Debes poder explicar cada punto con tus palabras.

## Qué agrega esta versión

- La estructura del proyecto en **Python con Flask**.
- La **base de datos SQLite** con todas sus tablas.
- La **página de inicio** con el diseño, que muestra cifras en vivo sacadas de la base.
- La **protección de formularios (CSRF)** y los archivos para no subir secretos a GitHub.

## Cómo funciona por dentro

**1. Flask y las rutas.** Una "ruta" conecta una dirección con una función. Cuando alguien entra a `/`, Flask ejecuta `inicio()` y devuelve la página:

```python
@app.route("/")
def inicio():
    return render_template("inicio.html", stats=servicio.estadisticas_publicas(db.get_db()))
```

**2. Plantillas con herencia.** `inicio.html` empieza con `{% extends "base.html" %}`: toma el marco común (barra y pie) y solo llena su contenido. Así el diseño se cambia en un solo lugar.

**3. La base de datos.** SQLite guarda todo en un solo archivo, `rescata.db`. `schema.sql` define las tablas y `datos_demo.py` llena unas de ejemplo. El archivo `.db` no se sube a GitHub: cada quien genera el suyo al correr la app.

**4. Protección CSRF.** Cada formulario lleva un código secreto de tu sesión. Antes de procesar cualquier formulario, `revisar_csrf()` comprueba ese código. Si falta o no coincide, responde error 400. Así otra página web no puede mandar formularios haciéndose pasar por el usuario.

**5. `tiene()`.** Es una ayuda para las plantillas: `tiene('comprador.catalogo')` dice si esa página ya existe. Gracias a eso, en esta versión la barra no muestra enlaces a páginas que llegan en versiones posteriores.

## Cómo probarla antes de subir

```
pip install -r requirements.txt
python app.py
```

1. Abre http://127.0.0.1:5000: debe verse la página de inicio.
2. Abre una dirección que no exista, como `/hola`: debe salir la página de error 404.
3. En otra terminal ejecuta `python -m pytest`: deben pasar **3 pruebas**.
4. Antes de hacer commit, ejecuta `git status` y revisa que **no** aparezcan `.env` ni `rescata.db`.

## Preguntas que te pueden hacer

- **¿Por qué Flask y SQLite?** Un solo lenguaje (Python), fácil de aprender y de explicar. SQLite no requiere instalar un servidor de base de datos.
- **¿Qué es el `.gitignore`?** La lista de archivos que Git no sube. Ahí están `.env`, porque tiene la clave de Gemini, y la base local.
- **¿Las cifras de la página de inicio son reales?** Se calculan en vivo desde la base, pero la base tiene datos de demostración, y así lo dice la página.
- **¿Qué es CSRF?** Ver el punto 4 de arriba.
